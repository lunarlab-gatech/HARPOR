# Implementing LiDAR guided sculpting in HARPOR

The feature is complete when the Blender agent can locate a local shape error from measured LiDAR returns, repair it, and demonstrate on the exported GLB that the surface moved closer to independently reserved measurements. A box with one bowed panel is the first acceptance case. The panel should become flat, its rim should still meet the adjoining faces, and an already correct box should receive no LiDAR edit. LiDAR supplies a physical reference where the sensor observed the object. The camera poses, association of returns with the object, and measurements themselves all have uncertainty. Unobserved surfaces can still receive the pipeline’s existing photo-guided repairs, which should be described as inferred.

Build this in two milestones. Steps 1 through 5 give the existing agent a trustworthy measurement and review tool. Steps 6 through 9 add deformation, candidate selection, and end-to-end verification. Keep the existing stage sequence. Stage A owns metric scale and placement, the agent owns the choice of local repair, and the controller owns the independent evaluation of each export. In the paths below, `J` is the web job directory, `run` is its selected reconstruction, and `control` and `work` are the two sides of an agent session. The new paths and interfaces below are proposed additions.

## Step 1 Establish a known geometry test

Start with an asymmetric, textured rectangular box in frame W. Generate a triangulated panel with enough interior vertices to deform and a marked rim. From a known clean mesh, generate noiseless rays from several known sensor poses and independent silhouette masks. Use analytic ray intersections with the six clean box planes as the reference so that a mistake in the production scorer cannot also make the fixture pass. Keep the clean box, make a second mesh by bowing the right panel outward by 20 mm at its center, and make a third by deleting that panel. Include oblique views, one sensor offset sideways from its camera, a nonidentity camera pose, and one surface that receives no measurements. Reserve the identity of the damaged panel, the clean dimensions, and clean vertex positions for test assertions. The agent should see exactly the information a captured job would supply.

Build the low-level fixture in a proposed `tests/test_lidar_geometry.py`. Reuse the camera and capture fixtures in `tests/test_webapp_views.py` and `tests/test_webapp_lidar.py` when exercising the higher-level stages. Start with three explicit expected outcomes. The clean box has near-zero first-hit range error within floating-point tolerance. The bowed panel produces a localized error with a known sign. Deleting it either exposes the far wall or causes a miss, and both outcomes count against the candidate. These cases establish what “better” means before introducing agent behavior.

## Step 2 Preserve measured returns through view selection

Extend `harpor/webapp/lidar.py:scale` where the source adapter has returned `samples, info, clouds`. The rosbag and Stray adapters already provide row-aligned measured pixels/depth and camera-space XYZ for views with usable geometry. For rosbag, use the calibrated LiDAR origin for that frame from `info["rays"]`, in the same rectified optical frame as the XYZ array. For Stray, use the existing upright, confidence-filtered XYZ from `stray.depth_points` and the aligned depth camera origin at zero. Record that it is the aligned-camera measurement model. A Stray export can supply enough pixel depths to estimate scale while lacking intrinsics for usable XYZ. Record that case as unavailable for sculpting. Record missing confidence separately from measured high confidence.

Write a versioned index and one numeric NPZ per pool view under a proposed `J/lidar/geometry/`. The minimum fields are pool name, source kind, original sample row ID, measured XYZ in camera meters, sensor origin in camera meters, measured pixel in the prepared image, and flags for mask membership, boundary ambiguity, source confidence availability and quality exclusions. Associate measurements with the prepared mask using the crop from `J/pool/prep.json` and `lidar_scale.source_to_grid`. Preserve integer pixel-center conventions, original row IDs and counts through filtering. Classify mask edges, mixed-depth neighborhoods and possible background returns conservatively. For offset sensors, use the existing projection and visibility diagnostics as supporting flags. An object mask by itself cannot establish that an offset LiDAR hit the camera-visible surface. Retain the measured endpoint even where DA3 differs from it. The scale estimator’s `used` mask has already been trimmed for agreement with DA3, and the viewer’s `_DIFF` values measure agreement with DA3. Using either as the geometry target would hide some of the defects this feature is meant to find.

Write completed arrays atomically with `harpor.fileio`, then the index, and finally the existing `pool/lidar.json` completion record with a reference to the matching index digest. Include capture/calibration identity, masks and crop identity, schema version, and per-view file digests. Preserve the acquisition timestamp and scan identifiers or scan time window used for each rosbag view while the adapter has them. For Stray, preserve the source frame index and timestamp when available. Version the adapter cache if new metadata is needed on cache hits. In `harpor/webapp/views.py:build_run`, copy the available measurement files for the selected pool names beside the existing viewer GLBs, under a distinct `J/run/lidar/geometry/` path. Use the actual ordered picks and `run/prep.json` mapping between pool name and run index. Handle a changed anchor, manual exclusions, and selected views that have no XYZ. A legacy job with only viewer GLBs should continue with photo-guided refinement and an explicit unavailable status. Rerunning the LiDAR and selection stages upgrades it. Exercise a cold read, a cache hit, an interrupted write, changed masks/calibration, a reordered selection, and a job with LiDAR off.

## Step 3 Freeze the session evidence in the mesh coordinate frame

At `harpor/webapp/agent_step.py:run`, load the selected measurement index alongside `mvsam3d.session_views`. Pass it as an optional keyword to `harpor/agent/controller.py:prepare_session`. Request sculpt supervision only when LiDAR was enabled for the job, its scale record is current, selection and placement agree on the applied metric scale, and the selected measurement files belong to that run. The current web caller passes `metric=True` even on jobs without LiDAR, so that flag cannot establish measured geometry. Preserve existing callers through the optional argument. A per-view failure should identify the affected view and allow the other valid views to contribute.

Use the final view-relative `w2c` from `run/cameras.json`. For each selected view, apply `inverse(w2c)` to both the measured endpoint and the sensor origin using `harpor.frames.transform_points`. These values are already in meters, and Stage A scales DA3 translations during selection. Applying the metric scale again, applying the fitted object pose to the measurements, or applying a second glTF axis conversion will place correct returns on the wrong surface. The stock glTF importer gives Blender world coordinates numerically equal to W for the posed asset. Preserve the measured prepared-image pixels for overlays. Reprojecting with DA3’s estimated intrinsics can disagree with the calibrated sensor projection, particularly near a distorted image edge. Test a nonunit scale, a rotated anchor, nonidentity glTF node transforms, a nonzero LiDAR baseline, a cropped rosbag frame and a portrait Stray frame. Check coordinates against hand-computed landmarks.

Keep authoritative arrays, cameras, masks, split assignments and settings under a proposed `control/lidar/`. Give the worker only the fitting measurements and a small manifest under `work/input/lidar/`. Split by distinct viewpoints before generating edit hints. Group adjacent frames with overlapping acquisition windows or nearly identical poses so that neighboring samples from the same scan cannot count as independent verification. Choose a deterministic verification group with overlapping object coverage and record the split. Start with two distinct fitting viewpoints and one reserved view observing a proposed patch for automatic acceptance. When scan identity or timing cannot establish independent groups, keep the affected patch in inspection mode. A dataset with fewer suitable views still gets overlays and an explanation of its coverage. Hash the evidence, split, settings and original mesh once per session. Use the same evidence for every candidate in that session. The host should score from its own copy regardless of modifications the worker makes under `/work`.

## Step 4 Measure the distance from the sensor to the candidate surface

Add a small host module, for example `harpor/agent/lidar_geometry.py`, with one scorer shared by previews, review and final validation. Load all triangle instances with their node transforms through `harpor.physics.mjcf.load_s`, which already maps the GLB into W. Build a ray index once per mesh. HARPOR’s agent environment already checks for `trimesh` and `rtree`. Ensure the documented local test installation includes the ray backend as well. A CPU implementation can use `RayMeshIntersector.intersects_id` with `multiple_hits=False` and `return_locations=True`, processing bounded batches and scattering the results back by the returned ray indices. With origin `o`, measured endpoint `p`, and first mesh hit `h`, use the unit direction `(p − o) / ‖p − o‖` and define the signed error as `‖h − o‖ − ‖p − o‖`. Negative means the mesh is too close to that sensor. Positive means it lies too far away. An oblique ray’s range differs from camera-axis depth. A ray with no hit has an explicit miss and a null distance. [Trimesh ray intersection API](https://trimesh.org/trimesh.ray.ray_triangle.html)

For each view and supported patch, report eligible rays, first hits, misses, median signed error, median absolute error and a high percentile of absolute error, all in meters. Keep per-view summaries and give distinct views comparable weight so dense phone depth cannot dominate a sparse view. Freeze ray IDs, weights and patch assignments from the original before comparing candidates. Build candidate comparisons on the same evidence, record paired-hit distances and changes in coverage, and count a jump to a far surface as a large error. A lower median obtained by losing rays is insufficient to accept a repair. Use a deterministic, spatially balanced sample and record any cap so reviewing the same GLB twice gives the same score. Cache by candidate SHA, original SHA, evidence digest and scorer/settings version. Test signed offsets on both sides of a plane, first-hit occlusion, misses, off-axis rays, multiple transformed primitives, reordered triangle indices and the deleted-panel fixture.

## Step 5 Put actionable evidence into Blender review

Before the first agent round, score the original and build a small set of candidate repair regions. Group neighboring, similarly oriented faces on the same connected surface where distinct fitting views show a consistent displacement beyond measurement uncertainty. Use the measured endpoints to check that the views support the same physical surface. Distinct views can see opposite sides of a thin panel. Face adjacency, facing direction, an eroded mask and rejection of grazing rays should prevent these sides from being combined. Freeze each region’s ID, bounds in W, representative normal, original fitting ray IDs and a surrounding comparison band. Select reserved ray IDs separately on the host from their original hits in the same region. Keep less certain regions visible as observations. A single disagreeing view, a broad discrepancy explained by a common shift of the whole object, or systematic disagreement between camera poses calls for an alignment finding. A diagnostic rigid fit can help recognize that case, but its fitted transform must never enter scoring or alter the delivered object.

Add baseline outputs alongside `work/original/previews/` and candidate outputs alongside each existing review receipt. Extend `controller.make_previews` and `harpor/agent/tools.py:review` to call the host scorer on `root/original.glb` and the host copy of the exported candidate. Give the agent a photo overlay with a fixed signed-error legend and physical units, a mark for a miss, and an indication of low support. Plot measured points using their stored image pixels. If displaying them in the cropped review, use the exact crop and scale from `harpor/agent/blender/review.py`. Also give the agent a short per-region summary with the original and current fit, support by view, and the coordinates needed to select the patch. Keep the sheet and receipt interface usable for jobs without geometry evidence. The milestone passes when a reviewer can identify the bowed face, its correction direction and the unsupported face from these outputs, and recognize the conflicting-view control without opening Blender or editing a vertex.

## Step 6 Give the agent two bounded sculpting operations

Place a headless Blender Python helper in the existing read-only agent tools mount, for example `harpor/agent/bin/lidar_sculpt.py`. The agent should be able to invoke it on `candidate.blend` with a reviewed patch ID, an operation and a strength. Supply the current review’s fitting correspondences, patch seed and normal in W, plus the source export and blend fingerprints. Confirm the saved scene matches the reviewed scene before applying an edit. For the initial sculpt, obtain a normal review receipt first. Resolve the patch in the current scene from its location, normal and connected mesh neighborhood. GLB reimport, material splitting and triangulation can renumber faces, so a face index from a prior export is an unreliable editing handle. If the correspondence is ambiguous, surface that fact to the agent.

Implement a plane fit first. Fit a robust plane to the measured endpoints on the patch, balance the views, and move the interior vertices toward the plane with the rim pinned and a smooth transition. Implement a second operation for curved geometry as a local push or pull. Use the normal component of the measured displacement, `dot(p − h, n)`, estimate a smooth displacement over the connected patch, and taper it toward its boundary. Bound motion per pass by the measured discrepancy and the patch size. Protect seams, sharp creases and attachment boundaries, and move coincident seam vertices consistently when they represent the same surface. Convert W displacements correctly into object-local coordinates, including nonuniform object transforms. Preserve UV coordinates, materials, topology and global transforms for these two operations. A coarse patch without enough movable vertices should give the agent a clear reason to choose another supported repair. Save the packed result through a temporary sibling file and atomically replace the working scene only after confirming finite vertices and valid face orientation. Keep the last reviewed checkpoint available for rollback.

The agent decides which patch needs attention, whether flatness or curvature fits the photographs, and whether to keep the result after review. Update `harpor/agent/prompts/__init__.py`, `harpor/agent/codex/AGENTS.md` and `harpor/agent/claude/SYSTEM.md` so both backends get the same workflow in build and repair rounds. Include an example from inspection through export, review, checkpoint and finish. Describe measured and inferred repairs separately in the handoff reason when both occur. Use existing deadlines, checkpoints and receipt handling. Exercise the helper under real headless Blender on the bowed panel, a smooth dent, a correct panel, and two nearby disconnected surfaces. Check the exported geometry, UVs, material assignments, and vertices outside the intended region.

## Step 7 Make host validation decide which candidate is delivered

Extend `harpor/agent/validate.py:check` to score the exact stored candidate against the host’s baseline and reserved rays. Bind cached reports to the full evidence key from Step 4. The current cache checks the GLB digest alone. For silhouettes, compute comparable per-view IoUs from host-owned masks and cameras at a fixed resolution using `mvsam3d.view_ious`. Review images under the worker’s writable directory are a visual aid. Decide that a patch improved only when the reserved views show an absolute-error gain beyond the repeatability tolerance, hit coverage is maintained within tolerance, and the surrounding surface and silhouettes have no meaningful regression. Return a separate status for a tie, insufficient local coverage, inconsistent registration, and a failed scorer. Distinguish a functioning scorer with insufficient evidence from an operational failure on an otherwise verifiable candidate. The latter needs a retry or an explicitly unverified handoff.

Put the policy in one versioned settings object. Include minimum independent views, minimum spatially distributed samples per view, grazing-angle limit, range repeatability, permissible coverage and silhouette changes, and maximum displacement. Use fixture-defined tolerances for synthetic tests. For a real source, estimate range repeatability on repeated captures of a static plane at representative ranges and angles, and estimate pose and mask variability from the same captures. Ship calibrated defaults by source and record the values used in each report. Until a source has a calibrated profile, allow its ordinary jobs to produce diagnostic overlays and select the synthetic profile explicitly in tests. Differences inside the measured repeatability band are ties. As a deterministic first comparison rule, require a gain greater than the configured range tolerance on the median of per-view patch medians, and reject a loss greater than tolerance in any well-supported verification view or protected region. Keep individual verified views visible in the evidence. A thin or weakly observed patch can remain diagnostic without turning a successfully completed photo repair into a failed job.

Wire the statuses through `validate.checks`, `counts`, `scope`, `feedback`, `controller.check_round`, candidate ranking and `harpor/agent/evidence.py`. Today every finding outside the `surface_` family counts as a failure, and equally passing candidates are ordered by source and version. Explicitly mark coverage and alignment notices as informational. Emit a local repair finding when a well-supported target remains or an edit causes a verified regression. Give the worker the affected fitting patch and the kind of failure, while reserving individual verification returns on the host. For eligible reviewed candidates, prefer repairs that resolve more of the same frozen targets with no verified regression. Where that count ties, compare the reduction in error on those same patches with equal patch weights, and apply the existing source/version ordering to differences inside the tolerance. Keep GLB validity, size checks and normal handoff requirements. Exclude a demonstrably worse mesh from delivery even if it is the only edited candidate. Fall back to an earlier acceptable checkpoint or the original with the correct verdict and reason. A good checkpoint and a later bad finish can occur in the same round. `select_deliverable` currently picks one handoff before measurement validation, so explicitly evaluate prior host-recorded checkpoint bytes if the finish is rejected. Preserve the checkpoint’s existing review status. Check both `best_candidate` and `select_candidate`, including the branch that can reuse the last unchanged handoff. Persist the winning candidate’s hash, evidence digest, before/after values, coverage and reason in `agent/evidence.json` through the existing scrubbed, finite-JSON publication path. Verify that `steps.next_glb` gives physics the geometry the host actually selected.

## Step 8 Deliver the feature through the normal job path

Use one mode with values `off`, `inspect` and `sculpt`. Add an optional `--lidar-geometry` to `harpor.webapp.agent_step` and the user-facing `harpor.webapp.run` CLI. Carry the requested mode in the start or resume payload, validate the enum with the other job settings in `harpor/webapp/server.py` and `harpor/webapp/jobs.py`, persist it as `job.json` field `lidar_geometry`, and have `harpor.webapp.steps.command` forward it when launching the agent. Read older job records with a documented default. Store the requested and effective modes with the session. Use `inspect` for initial real-capture trials. It generates diagnostics while keeping LiDAR findings informational. In `sculpt`, enable the edit instructions and host acceptance policy on qualified regions. A job with no usable LiDAR follows its existing refinement path. Preserve the existing skip for disabled agents or poor Stage A placement. Make `sculpt` the normal mode for qualified LiDAR jobs after the acceptance runs below, with an explicit override for comparisons. In `Runner.resume`, invalidate the agent and downstream outputs when only this mode changes, reusing valid reconstruction inputs and the existing agent key. The current agent-change branch also changes key handling, so keep those two decisions separate. Exercise both a fresh job and the existing retry/resume path. Document invocation, the sign convention, units and unavailable states in the README’s agent and LiDAR sections.

## Step 9 Verify the complete loop and calibrate it on a capture

Run the new analytic and sculpting tests together with `tests/test_webapp_lidar.py`, `tests/test_webapp_views.py`, `tests/test_mvsam3d.py`, `tests/test_validate.py`, `tests/test_agent_controller.py` and `tests/test_webapp_run.py`. Run the full suite with `.venv/bin/python -m pytest -q tests`. Extend the fake worker to exercise delivery and recovery deterministically, then run a real Blender export and reimport in HARPOR’s agent environment. Finally run a live agent from the normal job launcher on the damaged fixture. Verify from its actual review receipts that it identified the correct patch, selected an operation, inspected the result, and handed off the same GLB digest that the host scored. Include a candidate that improves its fitting rays but worsens a reserved view, a later regression after a good checkpoint, missing rays after panel removal, a valid texture-only repair, interrupted review, and reuse of the same GLB with a new calibration. On the 20 mm noiseless fixture, set an initial acceptance target of at least a 75% reduction in held-out median absolute error on the bowed interior, no lost verification hits, and less than 0.1 mm change at pinned or protected landmarks. Include an inward dent to catch a reversed correction. These numbers are synthetic fixture targets. Use measured repeatability for real captures.

For physical acceptance, capture a flat-sided object with independently measured dimensions from several viewpoints and measure at least one feature local to the intended patch, such as panel flatness against a straightedge. Cover a calibrated rosbag and an upright or portrait Stray capture, recording which sources have actually passed. Start from the same placed mesh and photograph set for each run. Compare the placed mesh, the ordinary photo-refined mesh and the LiDAR-sculpted mesh using one reserved measurement split. If the natural reconstruction already meets the physical tolerance, also inject the known bow into a copy of that reconstruction and compare both agent modes from that identical damaged starting point. Record local dimensional or flatness error, held-out ray error and coverage by view, silhouette changes, shape changes away from the patch, and review time on the target machine. Repeat with an already-correct mesh and with a deliberately misregistered view. Success means the feature improves the independently measured defect, protects correct surfaces, and abstains when registration is ambiguous. Verification views used for candidate selection measure generalization within that job. The independent physical measurements are what establish whether the final geometry moved closer to the real object.
