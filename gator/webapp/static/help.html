About HARPOR

HARPOR stands for High-fidelity Articulated sim-Ready Object Reconstruction. It turns a phone video, a rosbag or a Stray Scanner capture of one object into models for simulation:

  • meshes of the object, as it stood in the capture and turned upright;
  • its parts and joints, when it has moving parts;
  • its mass and materials;
  • MuJoCo, USD and URDF models.

Each job builds one object from one capture. The build picks sharp frames, masks the object with SAM 3, estimates depth with Depth Anything 3 (DA3), chooses the views, makes a mesh with MV-SAM3D and fits it to the masks. An agent then refines the mesh or sets the joints, and VoMP predicts the materials. Job status and the log lists every stage.

Record a capture

Capture one object. Walk around it and keep it in frame the whole time. Record with HDR off: HDR video gives flat colors, so the textures look washed out.

InputFilesNotes

Stray Scanner.zipZip the export folder of the Stray Scanner app first. The iPhone's LiDAR depth in it gives the metric scale.

Add a job

On the jobs list, drop the file on the Add a capture box, or press Choose a file. A file can be up to 20 GB.

The upload shows how much is sent and the time left. Keep the page open until it ends, because leaving the page stops it. Cancel upload stops it too.

When the upload ends, the job page opens and the app reads the input.

Camera topics of a rosbag

When a rosbag has more than one camera topic, the job asks you to choose one. The table gives each topic's preview frame, message type, number of messages, rate, image size and lens. Press Use on the topic to build from, and the app reads its frames.

Prefer a rectified topic, because MV-SAM3D expects undistorted images. The Lens column says:

  • rectified: the images are undistorted.
  • raw: the lens distortion is still in the images.
  • unknown: there is no camera_info next to the topic, so the distortion is not known.

Not usable lists the topics that cannot be used, each with the reason.

To change the topic later, press Change topic in the Inputs tab. It shows while the job is not running, in review or done. The table opens again, with in use next to the current topic. Keep the current topic closes it.

A bag read before the app listed LiDAR topics shows none. To list them, press Change topic and choose the same camera topic again. When the job is in review or done, this is not possible: add the bag again as a new job.

Review the views

With Review views before building on, the build stops after the view selection. Check the views, change them if needed, then press Build. Build uses the picked views as they are.

The top view

The plot shows the cameras seen from above, around the object:

  • ● a filled dot: a picked view, with its view number
  • ■ a square: a pick set to always use
  • ★ a star: view 0
  • ○ a hollow dot: a view that can be used but is not picked
  • × a cross: a view left out, because its mask is small or inconsistent
  • + the object

Views set to never use, and views with no mask, are not shown.

The summary line

It reads N of M views · coverage X° · spacing Y°. N views were picked of the M that you asked for. Coverage: every candidate is within X° of a pick, so a smaller number means that the picks surround the object better. Spacing: the two closest picks are Y° apart. Picks closer than 15° get a warning, and auto mode picks one view fewer while two picks are that close, down to 3 views.

The view cards

The picked views come first, in view order, then the other candidates. Each card shows the frame with its SAM 3 mask, its name and time, its status and these numbers:

q
The view's quality, from SAM 3's score, the mask's area, whether the mask touches the image border, the sharpness and the clipped pixels. Higher is better.
agree
How well the view's mask agrees with the other views, through DA3's depth, from 0 to 1.
N° from a pick
For a view that is not picked: the angle to the nearest pick.
LiDAR
With LiDAR, the view's own scale and point count. See Metric scale and LiDAR.

The status of a view:

picked
The selection uses the view.
locked
A pick set to always use.
available
The view can be used, but it is not picked.
small
The mask covers under 1% of the image, so the view is left out.
inconsistent
agree is below 0.5, so the view is left out. SAM 3 found something else or more than the object, or DA3 placed the camera wrong.
excluded
The view is set to never use.
no mask
SAM 3 found no mask of the object in the frame.

Change the views

Each card has two menus and a view 0 choice:

  • Use: auto lets the app decide, always use keeps the view in, and never use leaves it out.
  • Mask: top mask is SAM 3's mask with the highest score. mask i (score) takes another mask that SAM 3 found in the frame. not in frame says that the object is not in this frame.
  • The view 0 choice makes this view view 0. It shows on a pick that is not set to never use, and on a view set to always use.

After a change, the card says what will happen, such as Added when you select again. Build turns off until you press Select again, which runs the selection with your changes. Discard changes goes back to the views as they are.

To add another candidate, set it to always use and select again.

The selection fails when over a third of the masked views are inconsistent, or when fewer than 2 views can be used. Then set some views to always use or never use and select again, or press Pick frames manually. That opens the Settings tab in manual mode, with the candidate frames open.

With LiDAR, the top of the panel also gives the metric scale and the LiDAR check images: see Metric scale and LiDAR.

Parts of an articulated object

An articulated object has parts that move, such as doors, drawers or a lid. Turn on Articulated in the Settings tab for such an object. The build then lists its parts, splits the mesh into them, and the agent sets the joints. For a rigid object, the parts stages are skipped.

When the agent is off or skipped, the parts are split but get no joints, so physics welds them into one body.

The part list

Part list says who lists the moving parts. The VLM is the agent's model, and it looks at view 0.

  • VLM: the VLM lists the parts, and the build goes on.
  • VLM, then I check: the build stops after the VLM lists the parts, so you can check the list.
  • I type them: you type the list in the Settings tab.

Write one part per line, as name > parent : joint. For example:

cabinet body
door > cabinet body : revolute
drawer x3 > cabinet body : prismatic
  • The first line is the base. It has no parent, and it does not move.
  • revolute: the part turns about a hinge or an axle, like a door or a lid.
  • prismatic: the part slides, like a drawer.
  • fixed: the part does not move on its parent.
  • unknown: you cannot tell.
  • drawer x3 means three identical drawers.

The joint in the list is a guess. The agent sets the joints.

Check the part list

With VLM, then I check, the job stops at the Part list panel. It shows view 0 with the object's SAM 3 mask, the VLM's list, and its axis hints: a few words on where each hinge or slide is and which way the part moves. Edit the list if it is wrong, then press Build. Undo edits brings back the VLM's list. A part that keeps its name and joint keeps its axis hint.

How the parts are split

SAM 3 masks each part's name in every view used, the base included. The masks vote on every face of the posed mesh, and Blender cuts the mesh and fills the holes. The vote starts from every mask with a score of at least 0.4. It drops the masks that lie outside the object, cover the whole object, are the union of two or more others, or repeat a mask with a higher score. Part masks, in the Results tab, shows these masks, one color per part.

Parts not split off, in the Results tab, lists each group of masks of a listed name that did not become a part. So a name can show there and still have a part. not found means that no mask of the name was left in any view: SAM 3 found none with a score of at least 0.4, or the vote dropped them all. Otherwise the vote gives the reason: the group covers less than 0.3% of the surface, or fewer than half of the views that see it well and found the name hold it.

The agent and API keys

The agent works on the posed mesh. For a rigid object it edits the mesh in Blender. For an articulated object it sets the joints of the split parts. You choose it in the Settings tab:

  • GPT-6-Astra runs through the Codex CLI. It needs an OpenAI key, which starts with sk-.
  • Claude Opus 5.5 runs through the Anthropic API. It needs an Anthropic key, which starts with sk-ant-.
  • None runs no agent and needs no key.

Both models run at xhigh effort. The agent has 600 s to edit the mesh, or 900 s to set the joints. Time spent exporting GLBs does not count, up to 600 s. The agent is skipped when it is turned off, or when the mean mask IoU is below 0.5 (see Results). Physics then uses the posed mesh, or the split parts without joints.

GPT-6-Astra and the network

GPT-6-Astra runs the Codex CLI in a container that can reach the network. Text in your video or images, such as a sign or a label, could steer it to run commands that reach the network. These commands run on the GPU machine that runs the job. Claude Opus 5.5 runs its shell with no network access. If this matters to you, choose Opus.

API keys

Each job uses your own key, and your provider bills you for it. A key is one word of letters, digits, - and _. Use a key with a spending limit, and delete it at your provider when you no longer need it.

The page sends the key to the server when you press Start, Build, Select again or Retry, and it does not keep it. The server checks the key with your provider and keeps it in memory while the job needs it. It forgets the key when the job is done or cancelled, and when the server restarts.

When a stage needs the key again, a key field shows next to its button.

What the Results tab says about the agent

Agent
The model that ran, or off when the agent was turned off, or skipped with the reason.
Agent verdict
The agent's verdict when it called finish. For a refined mesh it is complete, unchanged or needs_review. For joints it is articulated, unchanged (no joints) or needs review. In brackets is where the result came from: finish, checkpoint, export or fallback_original. A checkpoint or an export means that the session ended without a valid finish, so the verdict is needs review. fallback_original means that the agent left no valid result, so its input was kept.
Agent reason
The agent's own words when it called finish. When the session ended without a valid finish, it is the defect noted at the last checkpoint, or the app's note on the export or the fallback. When the agent's result held your API key, the reason and the limitations are left out.
Limitation
A flaw that the agent says is still in its result, written when it called finish. The agent can list at most 3.
Joint changes
The set_joint calls that set or removed a joint, which the app accepted during the session. A change that added a problem to the joint tree was refused and undone, and it does not count.
Agent tokens
For Claude Opus 5.5: the tokens of the whole session, from its log: new input, output, cache reads and cache writes. A turn is one reply of the model.
Agent cost (estimate)
An estimate from the token counts at Claude Opus 5.5's prices per million tokens: $4 input, $20 output, $0.20 cache read and $5 cache write. In a turn with a refusal fallback, both tries count, each at its own model's prices. A try that failed and was sent again does not count, so the estimate can be low. A ? means that the log gave no cost. Your Anthropic bill gives the real cost.

Metric scale and LiDAR

The models need the object's size in meters. Without LiDAR, Depth Anything 3 (DA3) estimates the scale from the images. That scale is not measured, so sizes and masses can be off. With LiDAR, the scale comes from measured depth:

  • for a rosbag, the points of a LiDAR topic (PointCloud2 or Livox), linked to the camera by the bag's TF or by a calibration file;
  • for a Stray Scanner capture, the iPhone's LiDAR depth, which is already aligned with the color camera. A Stray job starts with LiDAR on.

A video has no LiDAR. The Use LiDAR for metric scale checkbox in the Settings tab turns it on or off.

How the scale is found

For each view, the lidar stage takes the LiDAR points inside the object's mask and divides each point's LiDAR depth by DA3's depth at the same pixel. The view's scale is the median of these ratios. The job's scale is the weighted median of the views that agree. The select stage multiplies DA3's depth and camera positions by it before MV-SAM3D, so every later size is in meters. Without LiDAR, the sizes come from DA3's own depth estimate.

Each view shows its scale and its number of points, and a word when the view is not used:

outlier
Its scale is more than 5% from the others' (or more, when the views spread more).
scattered
Its ratios spread too much: the middle half of them spans over 25% of its scale.
few points
The view has under 30 points in its mask.
no mask
The view has no mask.
no points
No LiDAR point falls on the view.

The lidar stage fails when fewer than 3 views have points, when fewer than 3 views or under half of them agree, when the spread is over 8%, or when the scale is outside 0.5 to 2. A scale outside 0.5 to 2 often means an inverted transform or wrong units.

Check images

LiDAR check images, in the review and in the failure panel, show each view's LiDAR points on the frame. The green line is the mask outline. Blue points are nearer than the scaled depth, and red points are farther. White points agree with it. When no scale was found, each view uses its own scale, and a view without one shows all its points white. Open an image to see it larger. When the points sit shifted or turned against the object, the calibration or the time offset is likely wrong.

The link between LiDAR and camera

For a rosbag, choose the LiDAR topic. The line under it says how the LiDAR links to the camera: linked by /tf_static (or /tf) with the chain of frames, Linked by the calibration, or No TF link: upload a calibration.

Upload calibration takes a .yaml, .yml or .json file, and it replaces the bag's TF. Its keys:

T_cam_lidar
A 4 × 4 transform in meters that takes LiDAR points to the camera's frame, before rectification. Its translation is at most 2 m; a larger one is likely in millimeters. T_lidar_cam, its inverse, works too, and so do FAST-LIVO2's Rcl and Pcl.
camera_axes
optical, the default: x right, y down, z forward. Or body: x forward, y left, z up.
K, D
Optional: the camera's intrinsics and distortion. Without K, it comes from the bag's camera_info.
time_offset_s
Optional: the LiDAR clock minus the camera clock, in seconds.
T_cam_lidar:
  - [0, -1, 0, 0.02]
  - [0, 0, -1, -0.05]
  - [1, 0, 0, 0.01]
  - [0, 0, 0, 1]
camera_axes: optical
time_offset_s: 0.0

Once the file is saved, the line under the button gives its name, the LiDAR's distance and turn from the camera, where K comes from (the file or camera_info), Body axes when the file uses them, and the time offset. Replace calibration and Remove change it.

When you change the calibration after the scale was found, Retry starts from the lidar stage. In review, the panel says Calibration changed, and Build finds the scale again, then stops in review.

When the scale fails

The LiDAR scale failed panel shows the lidar record with its check images, and LiDAR settings opens the LiDAR settings in the Settings tab. Then:

  • For a rosbag, upload or replace the calibration and Retry, or turn LiDAR off and build again.
  • For a Stray capture, turn LiDAR off or change the views, then build again. Retry reads the same depth and masks again, so it helps only after a file or disk error.

Inputs tab

The Inputs tab shows the input once it is read: its name and kind, a preview video, facts about the frames, and the views that the build used.

Preview and views

The app makes the preview video when it reads the input. A job read before the app made previews has none. The preview keeps only some frames, so it can show the nearest kept frame before the one you ask for.

Under Views used, click a view to see its frame in the video. The line under the video gives the view, its frame and its time. ★ marks view 0.

After the place stage, Mesh fit draws the posed mesh in red and the outline of the SAM 3 mask in green on each view. A mesh that strays from the green outline shows a poor fit.

Frame facts

The Video line (Stray capture for a Stray Scanner capture) opens the facts: frames, length, frame rate, size, codec and the number of candidate views.

The sharpness chart shows each frame's sharpness over time, compared with the median of the frames around it. The dashed line is 0.6 of that median, and the dots are the candidate views. The app cuts the input into equal time bins, about 2 per second and 16 to 32 in all, and takes the sharpest frame of each bin as a candidate. A bin gives none when that frame is under the line or badly exposed.

HDR video: colors may look flat. Record with HDR off next time: see Record a capture.

A Stray capture also says how far the frames are turned counterclockwise to stand upright, from gravity, and in how many of the frames that show gravity it agrees. It counts the frames with a depth image, with its size, and the frames with a confidence image. Its warnings follow.

For a rosbag, Change topic opens the camera topic table: see Camera topics.

Results

The Results tab shows the meshes in 3D viewers, then a list of facts. Drag to turn a mesh, and scroll to zoom.

Posed mesh
MV-SAM3D's mesh from all the views used, with its size, position and a small turn fitted to the SAM 3 masks. The log and the Agent row call it the Stage A mesh.
Split parts
For an articulated object: the posed mesh cut into parts, without joints. See Parts.
Refined
The agent's GLB: the posed mesh after the agent edited it in Blender, or as it was when the verdict is unchanged. Physics uses it.
Parts with joints
The split parts as the agent delivered them, in one GLB, with the joints that it set. The title says no joints when it set none. Physics uses it.

The title of the agent's viewer names the model that made it. Every mesh is in view 0's camera frame, where the viewer's up is the camera's forward axis, so the object looks tipped over. aligned.glb, in the Downloads tab, is the upright copy. The size under each viewer is the box around the mesh along view 0's camera axes, in cm. So a tilted object gives a box larger than the object.

Metric scale
The scale from LiDAR, or Depth Anything 3's estimate. See Metric scale and LiDAR.

Parts
Parts not split off and Part masks: see Parts.

Joints

Physics
Mass, center of mass and the materials: see Mass and materials.

Joints and links

Physics builds the MuJoCo, USD and URDF models from the GLB that the agent delivered. Each part becomes a link, and each joint that the agent set becomes a joint. A part without a joint is welded to the nearest part above it in the GLB's node tree, or else to the base. When the GLB has no joints, the models hold the whole object as one rigid body. That happens when the agent is off or skipped, or when it delivered no joints.

Joints
The number of joints in the GLB that the agent delivered, fixed joints included. With 0, physics welds the parts into one body. A ? means that the app could not read the GLB's joints.
Links
The bodies of the MuJoCo model (mjcf.json), one for each part of the GLB that physics used. 1 (no joints, one rigid body) means that the GLB had no joints.
Base
The link that the other links hang from. It is fixed to the world when the agent gave it a fixed joint to the world. Otherwise it can move freely.
Joint of a part
How the part moves on its parent, from the joint that the agent set: it turns about an axis (revolute, with its range in degrees), slides along one (prismatic, in cm) or is fixed. The range runs from the lower to the upper limit, where 0 is the part's pose in the mesh. none (welded to X) means that the agent gave the part no joint, so physics welds it as above.

Mass and materials

VoMP predicts the material of every occupied voxel of the aligned mesh, on a 64³ grid. An articulated object puts each link on its own grid. A link with no VoMP result, such as a thin lid with no occupied voxel, gets its collision hulls filled at the object's median density when the parts have joints. When they have none, it is left out.

Mass
The sum of density times voxel volume over the voxels of all links. Mass grows with the size cubed, so a 5% size error gives about a 16% mass error.
Center of mass
The mass-weighted mean of the voxel centers, and of any link filled from its collision hulls, as x, y and z in meters. The frame is that of the physics models: z up, x along the long side, and the origin at the center of the footprint at the bottom of the object.
Link masses
Each link's mass. (from hulls) marks a link filled from its collision hulls.
Mass note
Names the links that VoMP gave no result for, when the parts have no joints. The mass and the center of mass leave them out, and so do the MuJoCo, USD and URDF models, which still keep their shapes.
Young's modulus (median)
Stiffness, in pascals (Pa). 1 GPa is 1e9 Pa. In our tests VoMP v1.1 gave about 4 GPa to most objects, steel and glass included.
Poisson ratio (median)
How much the material bulges sideways when it is squeezed, with no unit (usually 0 to 0.5).
Density (median)
In kg/m³. The mass uses each voxel's own density, not this median. In our tests VoMP v1.1 gave about 1,000 kg/m³ to most objects.

The three material rows are medians of VoMP's prediction over the object's voxels. For an articulated object, the voxels of all links count, each by its volume.

Downloads

The Downloads tab lists the job's files by group, each with its size. A file downloads as <job id>_<name>, so the files of two jobs do not clash. The files hide while a build runs, because the build replaces them. Before results.zip exists, the tab lists the files made so far.

Meshes

posed.glb
The posed mesh in view 0's camera frame, in meters, with the scale from LiDAR when LiDAR is on, else from Depth Anything 3's estimate.
parts.glb
The split parts in one GLB, one node per part, without joints, in the same frame as posed.glb.
refined.glb
The agent's GLB, in the same frame as posed.glb. For an articulated object, each joint that the agent set is in its child part's node extras (gator_joint); a part without one has none.
aligned.glb
The GLB that physics used, turned upright, with the bottom at 0, the footprint centered on the origin and the long side on x (z up in MuJoCo, y up in glTF). Up is the object's own axis closest to the up of the table or floor under it in view 0, or to the cameras' mean up when no plane fits there. Materials that let light through are made opaque, because VoMP rejects them.

Simulation

model.urdf
A URDF of the object, built from the MuJoCo model's meshes and masses: one link when the GLB has no joints, else one link per part. Each part but the base gets the agent's joint to its parent, or a fixed one to the link that physics welds it to when the agent gave it none. A fixed base adds a world link. It needs urdf/meshes from results.zip.

Records

placement.json
The record of the place stage: the pose that puts the MV-SAM3D mesh in view 0's camera frame, the scale and pose fitted to the SAM 3 masks, and the metric scale. Its check gives each view's mask IoU and how close view 0's DA3 points lie to the mesh.
summary.json
VoMP's summary of the aligned mesh: the voxel counts, the median and the 5th to 95th percentile of Young's modulus, Poisson ratio and density, and the mass, center of mass and inertia of the rigid body. For an articulated object it adds each link's numbers and the links that VoMP could not voxelize.
lidar.json
The record of the lidar stage: the metric scale, each view's scale, point count and status, how the views were combined, the LiDAR source, and the link to the camera (for a rosbag the TF chain or the uploaded calibration; a Stray capture's depth is already aligned with the color camera). When no scale was found, ok is false and reason says why.
selection.json
The view selection: every candidate frame with its quality and status, such as picked or excluded, the picks in run order with view 0 first, the cameras seen from above, the warnings and the metric scale that select applied (null without LiDAR). ok is false when the selection failed, and the warnings say why.
parts.json
The record of the parts stage: each part's name, parent, guessed joint, share of the surface and box, then the parts that were not split off, with the reason. It also gives the seams between parts that touch, with up to 4 fitted lines that may be hinge axes.
mjcf.json
The record of the MuJoCo model: its inputs, versions, counts and start height. For an object with joints it also lists the links with their masses, the joints, the base, the welded parts and the pairs that do not collide. The model itself comes only in results.zip.

Retry, cancel and build again

Retry
On a failed or cancelled job. It continues from the first stage that is not done, and its label names that stage, such as Retry from sam3d. Read input again means that the input was not read yet. Back to part list means that the job stopped before you confirmed its part list. After a change of the calibration, Retry starts from lidar.
Cancel job
Stops the running stage. For the API key, see The agent and API keys.
Build again
In the Settings tab of a stopped job. It runs every stage with the settings in the form and replaces the results, so it asks first. In review the button says Start over.
Delete
The trash can at the end of a row in the jobs list. It deletes the job and its files, after it asks. It is not offered while the job runs.

Troubleshooting

A failed job

The error box under the status gives the failed stage and the reason. For example, masks: exit 1: out of memory names the stage, its exit code and the last line of its log. The Log tab opens with that stage's log, and Full log opens the whole file. Fix the cause, then Retry.

Messages

lidar: …
The LiDAR scale failed. See Metric scale and LiDAR.
the server stopped while this job ran; resume it
The server restarted during the build. Press Retry.
The server no longer holds the … API key
The server restarted while the job waited in review. Paste the key next to Build, then press Build.
Selection failed
The view selection needs your help. See Review the views.
Agent: skipped
Not an error: the agent did not run, and the row says why, such as a low mask IoU. See Results.

The page and the server

Cannot reach the server. Is the SSH tunnel up?
The page lost the server. When the server started, it printed the ssh -L command that forwards its port. Run it again, then reload the page.
Not logged in. Open the ?token= link the server printed.
This browser has no login for this server, for example after the server restarted with a new token. Open the URL with ?token= that the server printed. The server also writes it to ~/.config/gator/webapp.json.
live log lost
The live log stopped. Reload the page.
file type not supported
See Record a capture for the file types.
upload failed
The upload stopped, or the server refused the file, and the message says why. Upload the file again.
